# Isomorphism Registry

## What This Is

This is a collection of records that show how different areas of knowledge might be connected. Each record (called an ISO record) claims there's a structural match between two different domains — like physics and theology.

Each record includes:
- The mapping (how the two things match up)
- The swap test (can you swap the roles and still get the same result?)
- Predictions that go both ways
- Conditions that would prove the mapping wrong
- An honest label of what kind of mapping it is

## How We Test These Mappings

Every record gets checked against the **Four-Test Protocol** (HYP-ISO-001):

1. **Prediction Constraint** — Does the mapping let us predict things in both domains?
2. **Symmetric Breaking** — If you break one domain, does the other break the same way?
3. **Connection Density** — How many independent matches exist? (7+ means it's very unlikely to be random chance)
4. **Falsifiability Invitation** — Does the mapping clearly state what would destroy it?

Think of it like this: If you have two puzzles that fit together perfectly, you should be able to predict what piece comes next in both puzzles. And if you break a piece in one puzzle, the matching piece in the other puzzle should break the same way.

## How to Add a New Record

1. Copy `ISOMORPHISM_TEMPLATE.md`
2. Name it: `ISO-[NNN]_[Short_Description].md`
3. Fill in every field. Run all tests honestly.
4. Update this README's registry table.
5. Add the record to `Isomorphism_Registry.html`.

## Rules

- An isomorphism that can't be falsified isn't an isomorphism — it's a belief.
- "Analogy Only" is not a failure. It's an honest classification.
- The swap test is mandatory. If roles are interchangeable, the mapping is arbitrary.
- "OBSERVATION CONFIRMED, MECHANISM UNSOLVED" is a valid status. Observation precedes explanation.
